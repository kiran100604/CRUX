# CRUX design system — how to manage it

The whole visual language lives in **one file**: `crux/static/tokens.css`. Every
surface (dashboard `index.html`, setup wizard `setup.html`, the demo
`docs/demo.html`) reads those tokens. Change a value there → it changes
everywhere, in both light and dark mode.

## Where things live
| Concern | File |
|---|---|
| Colors, radii, type, shadows, **dark mode** | `crux/static/tokens.css` (the source of truth) |
| Dashboard components & layout | `crux/static/index.html` (inline `<style>`, uses `var(--…)`) |
| Setup wizard | `crux/static/setup.html` (links tokens, a couple of local aliases) |
| Promo demo | `docs/demo.html` — generated by `python scripts/build_demo.py` |

`tokens.css` is served at `/static/tokens.css` (see the `/static/{name}` route in
`crux/server.py`).

## Token layers (in `tokens.css`)
1. **Base palette** — raw values: surfaces (`--canvas/--soft/--card/--strong/--hair/--paper`), text (`--ink/--body/--muted/--muted2/--on`), accent trios (`--teal*/--peach*/--coral*`), `--green`.
2. **Semantic aliases** — role-based names to prefer in new code: `--surface-card`, `--text`, `--accent`, `--danger`, …
3. **Signal-tag colors** — the taxonomy: `--k-decision-*`, `--k-constraint-*`, etc.
4. **Radii / type / shadows** — `--r-sm…--r-xl`, `--pill`, `--sans/--mono`, `--shadow-*`, `--ring`.
5. **Dark mode** — `html.crux-dark { … }` redefines every token. No component CSS changes needed.

## Common edits
- **Rebrand a color:** change its base value in `tokens.css` (and its `.crux-dark` counterpart).
- **Add a new accent/tag:** add the `--k-foo-bg/--k-foo-fg` pair (+ dark), then a `.k-foo` rule in `index.html`.
- **New component:** style it with `var(--…)` tokens only — never hardcode hex, so dark mode and future rebrands keep working.
- **Dark mode toggle:** the nav button calls `toggleTheme()`, which toggles `.crux-dark` on `<html>` and persists to `localStorage('crux-theme')`. A tiny pre-paint script in each page restores it without a flash.

## Rule of thumb
No raw hex in `index.html`/`setup.html` — reach for a token. If a token doesn't
exist for what you need, add it to `tokens.css` first.
